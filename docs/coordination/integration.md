# Handoff tích hợp

Tài liệu vận hành ở [README.md](../../README.md), checklist ở [docs/acceptance.md](../acceptance.md), script trong `verification/`. Nạp `.dev/env.sh` tại `/Volumes/SmartDeskDev/smart-desk-display` trước khi cài hoặc build. Session hardware giữ serial và nạp.

## Kết quả phần mềm

- Dashboard và REST dùng cùng origin HTTP. Device API trong [device-api.md](device-api.md); preview TFT trong [display-contract.md](display-contract.md); proxy HTTPS trong [github-contract.md](github-contract.md).
- `verification/check_http.py device ORIGIN` đọc `/api/status`, `/api/config`, `/api/github`, dashboard và CSS/JS cùng origin. `--exercise-fixture` bổ sung POST cho mode, config, message, timer và mode lỗi trên fixture loopback. Lệnh mặc định chỉ đọc nên dùng được cho IP thiết bị khi có handoff.
- `verification/check_http.py proxy ENDPOINT --username octocat` kiểm tra contract 52×7, ngày UTC, padding, streak và lỗi username. Đã chạy qua HTTP loopback với handler proxy thật dùng GraphQL fixture, 2/2 check đạt. Log `.dev/logs/integration-proxy-fixture.log`. Chưa kiểm tra GitHub live hoặc TLS từ ESP32.
- Sau khi có `app.js`, đã build và giải nén LittleFS bằng `verification/check_littlefs.sh`. Bốn asset `index.html`, `styles.css`, `preview.js`, `app.js` khớp byte với `web/public/`; ảnh 1.966.080 byte. Log `.dev/logs/integration-littlefs.log`. Chạy lại nếu web thay đổi trước flash.
- `npm test` trong `github-proxy/` đạt 9/9 trên Node 22. Log `.dev/logs/integration-proxy-tests.log`. Các test giả lập upstream cho lịch, rollover UTC, cache, xác thực input, token vắng, user vắng, rate limit và timeout.
- Fixture của web đã chạy trên loopback. Smoke HTTP kiểm tra ba GET JSON, HTML và ba tài nguyên, năm lệnh đổi mode, cập nhật config/message, chuỗi reset/start/pause/resume/reset, mode lỗi giữ nguyên trạng thái. Chromium ở 390 px và 1280 px kiểm tra canvas 320×240, năm mode, gửi và lưu tin nhắn, lưu cài đặt, thao tác timer, không lỗi JS và không tràn ngang. Log `.dev/logs/integration-web-fixture-{0,1}.log`. Fixture không phản ánh Wi-Fi, NTP, Preferences hay TFT thật.

## Yêu cầu nạp bản tích hợp cho session hardware

Build tích hợp ESP32 DevKit V1 đã đạt với firmware, renderer và GitHub provider. PlatformIO báo RAM tĩnh 51.972/327.680 byte (15,9%), Flash chương trình 1.067.169/2.097.152 byte (50,9%), theo `no_ota.csv`. Firmware image 1.073.744 byte, LittleFS 1.966.080 byte. Log `.dev/logs/integration-release.log` và `.dev/logs/integration-release-fs.log` cho ảnh LittleFS cập nhật sau handoff firmware. RAM tĩnh trong build chưa đo được heap khi thiết bị chạy TLS và phục vụ dashboard.

[Handoff phần cứng](hardware.md) ghi ESP32-D0WD-V3 và flash 4 MB qua esptool, build smoke test đạt. Session hardware thực hiện nạp sau khi xác nhận module/J1. Sau khi xác nhận smoke test, dùng thư mục build riêng cho mỗi ảnh:

```sh
cd /Volumes/SmartDeskDev/smart-desk-display
source .dev/env.sh
export PLATFORMIO_LIBDEPS_DIR="$SMART_DESK_DEV/integration/libdeps"
export PLATFORMIO_DATA_DIR="$SMART_DESK_ROOT/web/public"
PORT=/dev/cu.usbserial-0001
PLATFORMIO_BUILD_DIR="$SMART_DESK_DEV/integration/firmware-build" \
  pio run -d firmware -t upload --upload-port "$PORT"
PLATFORMIO_BUILD_DIR="$SMART_DESK_DEV/integration/fs-build" \
  pio run -d firmware -t uploadfs --upload-port "$PORT"
pio device monitor -d firmware --port "$PORT" --baud 115200
```

SHA-256 tại lần build kiểm tra:

| Ảnh | SHA-256 |
| --- | --- |
| `firmware.bin` | `0bce222ab7d43dd99be7a40c6d8eba4b4be1dc0dda65110b6646c4793267fc46` |
| `littlefs.bin` | `b01a4cde17404872afe0abf8768dc79cabae52c40e998ae7d9a2358f8cf14689` |

Nếu nguồn thay đổi trước khi nạp, build và kiểm ảnh lại rồi ghi hash mới. Dùng cùng lệnh PlatformIO và thư mục tương ứng ở trên, đổi target `upload` thành build mặc định và `uploadfs` thành `buildfs`. Xác minh LittleFS bằng `bash verification/check_littlefs.sh "$SMART_DESK_DEV/integration/fs-build/esp32doit-devkit-v1/littlefs.bin"`. Sau nạp, ghi splash/AP, ảnh TFT nếu có, và origin LAN vào `hardware.md`. Giữ thông tin xác thực Wi-Fi ngoài repo và log. Integration sẽ chạy `python3 verification/check_http.py device ORIGIN` qua LAN và đối chiếu các mục còn lại của [checklist nghiệm thu](../acceptance.md). Cần người tại bàn quan sát TFT, thao tác Wi-Fi nếu thiết bị đang ở setup, và thử ngắt/cấp nguồn USB. GitHub thật cần URL proxy HTTPS với token chỉ ở server. Kết quả fixture đã đạt, các bước vật lý và GitHub thật còn chờ.

### Kiểm tra lại sau thay đổi source

Lần recheck trung gian báo lỗi macro `IN6_IS_ADDR_V4MAPPED` trên lwIP của Arduino-ESP32 2.0.17. Firmware owner đã xử lý, build và kiểm ảnh ở trên đã đạt. Dùng hai đường dẫn mới `.dev/integration/firmware-build/` và `.dev/integration/fs-build/`. Lần thử dùng chung một thư mục build đã quan sát PlatformIO dọn mất `firmware.bin` khi chuyển sang target `buildfs`.

## Nghiệm thu LAN sau demo

Baseline bản demo tại `http://192.168.88.192/`. Hardware xác nhận TFT smoke test bằng quan sát trực tiếp, provisioning vào Wi-Fi, bốn asset LittleFS khớp nguồn, dashboard và ba GET trả HTTP 200. Lần đọc của integration cho thấy NTP UTC+7, đồng hồ lệch khoảng 1 giây so với Mac. Bản đang chạy thiếu `wifi.ip`, `wifi.hostname`, `github.lastSync` và `github.error`, nên strict check chưa đạt. macOS chưa phân giải được `esp32-display.local`. Pomodoro đang paused ở 24:48; chưa thay đổi timer. Đã lưu snapshot trước reboot của cấu hình và trạng thái vào thư mục kiểm thử trên SSD.

Chờ boot bản firmware đã sửa từ [handoff phần cứng](hardware.md) để so sánh cấu hình trước/sau, kiểm tra strict schema và thử mDNS lại. Chờ [handoff proxy](github.md) có endpoint live và tài khoản hiển thị được xác nhận trước khi ghi GitHub settings.

### Bản sửa 1.0.1

- Mac kiểm tra strict qua IP đạt ba GET JSON, HTML và ba asset. Đã có đủ key nullable. Sau boot, thấy cả trạng thái NTP chờ (`epochSeconds: null`) và đồng bộ UTC+7, chênh -1 giây so với Mac. Bốn file phục vụ qua LAN khớp byte với `web/public/` tại lúc kiểm tra.
- ESP32 tự quay lại `192.168.88.192`, Wi-Fi connected và AP setup tắt. Toàn bộ `GET /api/config` sau flash khớp snapshot trước flash và mode khởi động là `github`. Timer paused trước đợt nạp trở về idle 25:00 sau boot theo thiết kế.
- mDNS còn lỗi phân giải ở Mac (curl timeout 5 giây). `curl --resolve esp32-display.local:80:192.168.88.192 http://esp32-display.local/api/status` trả 200. Lệnh này chỉ kiểm tra định tuyến HTTP và Host. Truy cập qua IP. Log `.dev/logs/integration-1.0.1-lan.log`.
- Endpoint HTTPS Vercel đã phản hồi; lần probe với `octocat` trả HTTP 503 `proxy_unconfigured`. Kết quả này chỉ xác nhận server HTTP phản hồi qua HTTPS từ Mac, chưa có dữ liệu GitHub live. Chưa ghi GitHub settings lên ESP32.
- Pomodoro thật: bắt đầu một timer QA từ Chromium khi thiết bị idle. Sau khi đóng toàn bộ Chromium, API đo 1.500 → 1.489 giây trong 11,1 giây. Mở lại dashboard thấy timer tiếp tục chạy. Kết thúc timer QA và xác nhận idle 25:00 ban đầu. Log `.dev/logs/integration-1.0.1-timer.log`. Chưa quan sát đếm ngược trên TFT.
- Persistence thật: đảo tạm `clockShowSeconds` qua API, đọc xác nhận, restart bằng API khi timer idle. ESP32 quay lại LAN, uptime 4 giây, giữ giá trị mới và mode khởi động `github`. Khôi phục cài đặt đồng hồ rồi đối chiếu toàn bộ config với baseline. Strict HTTP chạy lại đạt. Đây là reboot qua API, chưa có phép thử rút nguồn USB. Log `.dev/logs/integration-1.0.1-{reboot,post-reboot-http}.log`.
- Handoff GitHub xác nhận endpoint Vercel dùng chuỗi về GTS Root R1. CA này có trong ảnh build riêng của GitHub session và cần xác nhận ảnh đã nạp trước khi test ESP32. Proxy production cần token chỉ đọc dữ liệu công khai qua [Vercel Environment Variables](https://vercel.com/lilzahs-projects/smart-desk-github-proxy/settings/environment-variables) và một lần redeploy sau khi lưu. Sau đó chạy strict proxy với username đã xác nhận, lưu hai trường GitHub trên ESP32, kiểm tra `/api/github` có `state=live`, username, 364 ô, tổng/streak/repo và `lastSync` hợp lệ. So sánh với phản hồi proxy và giữ nguyên các cài đặt khác.
